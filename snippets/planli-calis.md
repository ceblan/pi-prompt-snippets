Do not start coding immediately. First, produce a clear step-by-step implementation plan that covers:
1. Which files will be created, modified, or deleted.
2. The order of changes and why that order matters.
3. Potential risks or edge cases you foresee.
4. How you will verify the result (tests, manual checks, etc.).

Use the `todo` tool to track every step as a task — create all tasks up front with proper dependencies (blockedBy), mark each in_progress before starting it, and mark it completed when done. This keeps progress visible and resumable.

Present the plan and wait for my approval before executing any step. If the plan changes mid-execution, pause, update the todo list, and inform me.
